# PETShop

PETShop — это REST API на Go для работы с пользователями, товарами и заказами.

Проект разрабатывался поэтапно в четырёх версиях. Каждая версия добавляет новую функциональность и новые приёмы работы с базой данных и API.

## Технологии

- Go
- PostgreSQL
- Docker / Docker Compose
- chi router
- pgx
- SQL migrations

## Версии проекта

### V1 — Пользователи и товары

Базовые CRUD-операции для пользователей и товаров.

Реализовано:

- создание пользователя;
- получение списка всех пользователей;
- получение пользователя по email;
- создание товара;
- получение списка всех товаров;
- получение товара по ID;
- обновление товара;
- удаление товара.

Основная цель версии — работа с REST API и базовыми SQL-операциями в PostgreSQL.

### V2 — Заказы и позиции заказа

Добавлены заказы и товары внутри заказов.

Реализовано:

- создание заказа;
- добавление товара в заказ;
- получение заказа по ID;
- получение позиций заказа;
- получение заказов пользователя по email;
- автоматический пересчёт общей стоимости заказа.

Основная цель версии — работа со связями между таблицами базы данных.

### V3 — Checkout и транзакции

Добавлена логика оформления заказа через PostgreSQL transaction.

Endpoint:

```text
POST /checkout
```

Во время checkout приложение:

1. находит пользователя;
2. создаёт заказ;
3. проверяет остаток товара;
4. уменьшает количество товара на складе;
5. создаёт позиции заказа;
6. рассчитывает итоговую стоимость;
7. создаёт запись в таблице `transactions`;
8. выполняет `COMMIT`.

Если на любом этапе возникает ошибка, выполняется `ROLLBACK`.

Благодаря этому не может возникнуть ситуация, когда часть заказа сохранилась, а часть — нет.

Основная цель версии — работа с транзакциями и атомарностью операций.

### V4 — Аналитика

Добавлены аналитические SQL-запросы с использованием `JOIN`, `GROUP BY` и `SUM`.

История заказов пользователя:

```text
GET /users/history?email=alice@example.com
```

Возвращает информацию о заказах пользователя, включая:

- ID заказа;
- товар;
- количество;
- итоговую стоимость заказа;
- статус транзакции;
- дату создания.

Популярные товары:

```text
GET /products/popular
```

Товары группируются по ID, а общее количество проданных единиц рассчитывается через:

```sql
SUM(order_items.quantity)
```

Основная цель версии — практика SQL-запросов с объединением таблиц и агрегацией данных.

## API

### Пользователи

```text
POST /users
GET  /users
GET  /users/{email}
GET  /users/orders?email=alice@example.com
GET  /users/history?email=alice@example.com
```

### Товары

```text
POST   /products
GET    /products
GET    /products/{id}
PUT    /products/{id}
DELETE /products/{id}
GET    /products/popular
```

### Заказы

```text
POST /orders
GET  /orders/{id}

POST /orders/{id}/items
GET  /orders/{id}/items
```

### Checkout

```text
POST /checkout
```

### Проверка состояния приложения

```text
GET /health
```

## Переменные окружения

Создайте файл `.env` на основе `.env.example`.

Пример:

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=postgres
DB_HOST=postgres
DB_PORT=5432
```

## Запуск через Docker

Запуск проекта:

```bash
docker compose up --build
```

После запуска API будет доступно по адресу:

```text
http://localhost:8080
```

PostgreSQL и миграции запускаются через Docker Compose.

Остановка проекта:

```bash
docker compose down
```

Остановка проекта с удалением volume базы данных:

```bash
docker compose down -v
```
